### 2026-06-22 — doh-flight-checker — .gitignore missed .env exclusion
- **What happened:** The project scaffold didn't exclude `.env`; caught later during the Market Compass security pass rather than at creation time.
- **Lesson:** Scaffolding steps silently skip security defaults unless checked explicitly.
- **Rule going forward:** Every new project's first commit must include a `.gitignore` that covers `.env`/`.env.local`/credentials — verified, not assumed (now in secure-coding.md checklist).

### 2026-07-02 — market-compass — GitHub Pages first deploy required manual settings
- **What happened:** Deploy failed 3× at `deployment_queued`: Pages source and Actions write-permissions had to be set manually in repo Settings before any workflow-based deploy could succeed; `enablement: true` was rejected ("Resource not accessible by integration").
- **Lesson:** First-ever Pages deployment on a repo is an account-settings problem, not a workflow problem — retrying the pipeline cannot fix it.
- **Rule going forward:** Before the first Pages deploy on any repo, confirm with the user: Settings → Pages → Source = GitHub Actions, and Settings → Actions → Workflow permissions = Read and write. Escalate to the user after 2 failed identical attempts (codex-rescuer rule 5).

### 2026-07-10 — market-compass — parallel sessions on one branch cause push rejections
- **What happened:** Multiple sessions pushed to `claude/jolly-newton-5uctey` simultaneously; pushes were rejected and required fetch+merge before every push, and one rerun failed on a stale duplicate artifact.
- **Lesson:** Shared-branch parallel work needs fetch-merge-push discipline every time, and reruns of partially-failed workflows can collide with stale artifacts — a fresh run is safer.
- **Rule going forward:** Always `git fetch` + merge before push; prefer a new triggering commit over rerunning a failed workflow when artifacts may be stale.

### 2026-07-15 — market-compass — Predic panel: the data-source gate is the whole engagement, not a detail
- **What happened:** A "build a 17-section equity-research report panel" feature-add turned entirely on one reconnaissance finding — the app is PSX-Data-Portal-only and no free source publishes PSX financial statements, so ~11 of 17 sections have NO real data and could only be filled by fabricating figures (Constitution-forbidden). Routed as a scoped feature-add (not fresh Pattern A): architect data-source gate → adversarial plan-review (QA + auditor, both PASS-WITH-CONDITIONS) → user resolved the fork (PSX-only, honest-and-thin, keep verdict + add disclaimer) → backend engine + frontend UI (sequenced on one branch) → QA verify. Shipped a fork-agnostic engine whose `SourcedFigure` discriminated union + `guard()` makes fabrication structurally impossible; unavailable sections render honest N/A. 38 Predic tests green, tsc 0, build 0. Auditor caught that a numeric BUY/SELL verdict crosses into regulated-investment-advice territory and that `VITE_`-prefixed keys leak into the client bundle.
- **Lesson:** For any "generate an analyst/report/insight" feature, verify the real data supply BEFORE any UI/spec work — the honest answer may be "this cannot be built as asked," and surfacing that fork is the deliverable. Enforce no-invented-data in the TYPE SYSTEM (a value that structurally cannot exist without {source, asOf}), not in review. A rendered verdict/score on real securities is a governance surface (disclaimer adjacent to the verdict, keys server-side only), independent of the data gap. Also: full-suite runs surface pre-existing red tests — always separate "did we regress" (check `git diff --name-only` on the failing file) from "was it already broken."
- **Rule going forward:** Feature requests that produce numbers/verdicts must (1) pass a data-source gate first with an explicit sourceable-vs-blocked matrix, (2) route every figure through a guard constructor so fabrication is a compile error, never a placeholder, and (3) get an auditor pass whenever output could read as advice or a record. `VITE_`-prefixed env vars are client-public by construction — never a secret. Pre-existing test failures on an untouched file are not a regression; prove it with the diff before claiming or denying a green suite.

### 2026-07-10 — catch-the-falling-stars — conditional module.exports makes browser games unit-testable
- **What happened:** Full 6-phase engagement on a zero-dependency canvas game. Structuring game.js as pure-logic → engine → DOM adapter, with `if (typeof module !== 'undefined') module.exports = {...}`, let Node run 21 real assertions (collision, difficulty, scoring, storage sanitization, end-of-round precedence) against the exact shipped file — no browser needed for the QA gate. The adversarial Plan Review Gate caught 8 timing/state edge cases (pause-drift, timer-vs-lives race, blur-from-non-PLAYING) before a line of code existed.
- **Lesson:** Layer browser code so its pure logic is requireable, and run the plan through adversarial review first — both turn "should work" into command-output evidence cheaply. Also: security greps need manual triage (comments and `content=` attributes false-positive on innerHTML/on*= patterns).
- **Rule going forward:** Every browser-JS deliverable exposes its pure logic via conditional module.exports and ships with a Node harness executed in Phase 4; grep-based security scans must show the matched lines, not just counts.

### 2026-07-31 — gold-signal-analyzer (Cycle 5) — pick the STRUCTURALLY-closest precedent for a new store, keep the wizard's validation testable/converter-free, and surface-but-block the live seam
- **What happened:** Added the first-run setup wizard (FR-28) to the Cycle-4 read-only WPF shell — captures/validates/persists non-secret config (data source, gold symbol, loopback connection settings, account balance) and gates the dashboard on first launch. Three forks resolved toward "no new dependency + testable-VM / dumb-XAML": (1) **persistence placement** — the spec's NFR text sketched an Application/Infrastructure split (the `IJournalStore`/SQLite precedent), but the *structurally closer* precedent is `IAcknowledgementStore`/`FileAcknowledgementStore`, which lives ENTIRELY in `Presentation` (net8.0, does file I/O, referenced by the test project) — same shape of problem (a first-run gate backed by a tiny persisted file). Chose Presentation (`ISetupProfileStore`+`InMemory…`+`JsonFileSetupProfileStore` via in-framework `System.Text.Json`), documenting the NFR's literal placement as the rejected alternative; every NFR *acceptance* still met. (2) **live source = surfaced-but-blocked** (D5-2): `Mt5Live` is listed with `IsSelectable=false` and selecting it is a validation failure carrying the exact C-3 named-approver reason — honest about the seam without opening it. (3) **collect NO secret** (D5-3): the wizard performs no connection so it needs none; `SetupProfile` has only a logical `CredentialKey` *name*. 22 net-new xUnit (178→200) + 19 Python green; full+explicit-WPF build 0/0; order grep = 1 doc-comment false-positive (0 real); 0 new `PackageReference`; Testing.dll absent from Release. One test-only defect fixed in-gate (see lesson).
- **Lesson:** When a spec's NFR pins an implementation *placement* but a closer structural precedent exists, follow the precedent and record the deviation explicitly — placement is an implementation choice within the NFR, not a constitutional standard, as long as every NFR *acceptance* (durability-via-fresh-instance, no new package, dumb XAML) is still met. A wizard is fully headless-testable if the step machine + per-step validation + `CurrentError` live in a net8.0 VM and the XAML is a **hidden-header `TabControl` bound to `CurrentStepIndex`** (collapse TabItem headers via `ItemContainerStyle`; the selected tab's content still renders — no custom converter). Reuse existing invariants instead of reimplementing: `BridgeEndpoint.Parse` gives loopback-only validation and its exact error message for free. The test-only defect paid once: **`CurrentError` reflects the CURRENT step**, so asserting it equals a step-2 error while the VM is still on step-0 (Welcome, whose error is null by design) fails — navigate to the step under test before asserting step-scoped derived state; assert step-*independent* rules via the public `ValidateStep(index)` directly. Extend an EXISTING reflection guard (convert the `Mt5ConnectionOptions` no-secret `[Fact]` to a `[Theory]` covering `SetupProfile` too, add `otp`) rather than writing a parallel one — one guard, two types, can't regress. Prove "no secret" both structurally (no secret member) AND behaviourally (scan the persisted JSON).
- **Rule going forward:** For a "new persisted store" slice, choose the precedent that matches the *shape* of the problem (tiny first-run marker → the acknowledgement gate in Presentation; heavyweight cross-cutting store → the Infrastructure split), and if that contradicts an NFR's literal placement wording, follow the closer precedent and document the rejected alternative in the arch fork. Build multi-step wizards as a testable VM step-machine + hidden-header TabControl on `CurrentStepIndex` with precomputed selectability/validation so XAML carries zero converters. Reuse construction-time validators (`BridgeEndpoint`, `GoldSymbolResolver`) and surface their messages verbatim. When asserting step-scoped derived state (`CurrentError`), first navigate the VM to that step; use the pure `ValidateStep(i)` for step-independent checks. Surface-but-block a gated capability (list it, fail its selection with the exact approver reason) rather than hiding it. Extend existing safety-guard tests to cover new config types; prove no-secret structurally + on the persisted artifact. Re-run the FULL solution build + explicit WPF build; independently re-confirm the prior green count on the working tree before starting.

### 2026-07-30 — gold-signal-analyzer (Cycle 4) — draw the chart with a testable geometry VM (no charting lib), and make notifications a passive record with no command so INV-1 stays structural
- **What happened:** Added charts (FR-27) and notifications (FR-30) to the Cycle-3 read-only WPF shell, keeping it read-only. Two architecture forks resolved toward "no new dependency + keep the testable-VM / dumb-XAML split": (1) **chart = built-in WPF `Canvas`/`Polyline`/`Rectangle` fed by a pure `net8.0` `ChartViewModel`**, not a charting library (LiveCharts/OxyPlot/ScottPlot rejected — heavyweight, needs an offline-unavailable restore, and buys interactivity D4-1 doesn't need); (2) **notifications = in-app only** (email/SMS/push rejected as secret+egress against INV-2; OS toast deferred to FR-34 packaging since it needs app-identity registration). Indicator math stayed in Application (`ChartSeriesBuilder` reuses the existing `Indicators.EmaSeries` — zero new indicator code to verify); Presentation does only geometry (price→pixel) and dedupe. The notifier (`SignalNotifier`) is a passive surface: `Observe(analysis)` raises a read-only `NotificationViewModel` for a new actionable signal, deduped by direction inside a cooldown (injected `IClock`, ManualClock-tested), Neutral inert — and it has NO command member at all. 20 net-new xUnit (158→178) + 19 Python green; full+explicit-WPF build 0/0; order-surface grep = 0; no new `PackageReference`; disclaimer banner kept docked Top *outside* the new `ScrollViewer` so it stays always-visible.
- **Lesson:** A candle chart is fully unit-testable without a display if you split it: a pure Application builder emits `ChartData` (bars + null-during-warmup overlay series), a pure Presentation VM emits **plain (X,Y)/pixel geometry** asserted against *hand-computed* coordinates, and the XAML only binds shapes — precompute derived pixel values (`BodyHeight`/`WickHeight`/`WickX`) on the geometry record so the view needs **no value converters** (converters are logic, and logic in XAML escapes the headless test gate). Two silent traps paid once: (a) `Indicators` is BOTH a namespace and the class, so `Indicators.EmaSeries` binds to the namespace → `CS0234`; alias it (`using IndicatorMath = ...Indicators.Indicators;`). (b) The flat-series case (`max==min`) divides by zero in price→Y — guard it to mid-height and test it. For a UI slice, widening a shared VM constructor (2→4 args) breaks prior cycles' call-sites that the *new* tests won't touch — only the **full build** catches it, so build the whole solution, not just run the new tests. Make "no execution" structural on new surfaces too: a notification with no `ICommand` cannot be wired to a trade, proven by a reflection test that no member name contains open/close/buy/sell/execute/submit/order/trade/place.
- **Rule going forward:** For any chart/visualisation slice, keep indicator math in the tested calc layer, put price→pixel geometry in a pure VM asserted against hand-computed coordinates, precompute all derived draw values so the XAML carries zero converters/logic, and cover the degenerate inputs (empty/one-bar → no fabricated geometry; flat series → no divide-by-zero). New notification/alert surfaces must be passive records with no command (reflection-proven) so INV-1 stays structural. Prefer built-in drawing primitives over a charting library unless interactivity is a real requirement and the package is known-cached. Re-run the FULL solution build (not just new tests) after widening any shared constructor, and keep the always-visible disclaimer outside any scroll container. Notifications default to in-app; external channels/OS-toast are separate, later, and gated (toast pairs with packaging FR-34).

### 2026-07-30 — gold-signal-analyzer (Cycle 3, C-1 closure) — `dotnet test <sln>` does NOT build the GUI/entry project, and a UI is where the disclaimer + no-execution invariants get tested for real
- **What happened:** Built the UI/dashboard shell (FR-26/FR-35) to close CEO condition C-1 (the "not investment advice" disclaimer that had no UI to live in). Kept WPF (owner framing; confirmed feasible — SDK 8.0.100 + WindowsDesktop 8.0.0 runtime present). Split the work into a **plain net8.0 `Presentation` project holding every view-model** (INotifyPropertyChanged + ICommand are in the base framework, so full MVVM needs no WPF ref) + a **thin net8.0-windows `Wpf` XAML shell** with no logic, so the existing net8.0 test project exercises all UI logic headlessly. Added a pure `Application/Analysis/SignalAnalysisService` facade composing the existing stages (there was no composition point before). Scoped the slice **read-only display** — no paper Buy/Sell/execute surface at all — to keep the disclaimer-closure work free of execution risk. 15 net-new xUnit tests (143→158) + 19 Python green; C-1 CLOSED via three tested controls (first-run persisted acknowledgement gate + always-visible banner + single audited `DisclaimerText` source). C-3 (live/orders) stays OUT.
- **Lesson:** `dotnet test <solution>` only builds the test project and its dependencies — a WinExe/GUI entry project that nothing references is **not built**, so a green test run is NOT proof the app compiles. An explicit `dotnet build` of the WPF/entry project caught a real error the test run masked: the bare identifier `Application` in `App.xaml.cs` collided with the `GoldSignalAnalyzer.Application` namespace (fix: don't restate the base type — the XAML-generated partial already supplies `System.Windows.Application`). A UI is exactly where FR-22 ("score", never "N% probability") and INV-1 (no order surface) must be re-proven by grep + reflection, because a dashboard is the easiest place to sneak in a "78% probability" label or a Buy button. Also: put the exact regulated-advice phrase ("not investment advice") **literally** in the audited text — a negated paraphrase ("nothing it displays is investment advice") fails a compliance substring check and is weaker for an auditor.
- **Rule going forward:** For any slice with a GUI/entry project, run an explicit `dotnet build` of that project in the verification gate — never treat a green `dotnet test` as proof the app compiles. Keep UI logic in a plain (non-WPF) view-model project referenced by the test project; ship a dumb XAML shell. Re-prove no-fabrication (Neutral shows reasons not levels; open trades show blank P&L), no-probability-framing, and no-execution-surface by test + grep on every UI slice. Close named CEO conditions one at a time through the CEO gate; keep intentionally-deferred conditions (C-3 live/orders) explicitly OUT rather than rolling them into "done."

### 2026-07-30 — gold-signal-analyzer (Cycle 2, C-2 closure) — a "durable" store is only durable if a second connection on the same file reads it back
- **What happened:** Resumed a mid-flight engagement whose analytical core was already CEO-APPROVED-with-conditions. First re-ran the claimed green state on the actual uncommitted tree (137 xUnit + 19 Python, Testing.dll absent) rather than trusting the phase doc — it held. Then built the one named buildable carry-forward, C-2: `Infrastructure/Persistence/SqliteJournalStore` on `Microsoft.Data.Sqlite.Core` + `bundle_e_sqlite3` (only `.Core` + bundle were cached, not the metapackage — referencing both is functionally identical). 6 new tests took 137→143. CEO gate approved the closure; C-1 (disclaimer, ships with the absent UI) and C-3 (live/order, named-approver gate) stay open by design — explicitly NOT a go-live.
- **Lesson:** A persistence test that reuses the same store object proves an in-process cache, not durability — every "durable" assertion must reopen a *fresh* store/connection on the same file and read back. Store monetary `decimal` as invariant-culture TEXT, never SQLite REAL (IEEE-754 double silently corrupts money) — prove it with an exact many-digit value (1993.12345678m) that REAL couldn't hold. When only `Microsoft.Data.Sqlite.Core` + a `SQLitePCLRaw` bundle are cached, reference both and call `SQLitePCL.Batteries_V2.Init()` — no need for the metapackage or a network restore. After adding a dependency to a production project, re-run the assembly-graph safety gate (Testing.dll absent, no order surface) because the dependency graph changed.
- **Rule going forward:** Durable-store tests reopen a new connection/instance on the same file before asserting; money persists as invariant TEXT with an exact-value round-trip test; when resuming an engagement, independently re-run the claimed green state on the working tree before building the next slice, and re-verify structural safety invariants after any new production dependency. Close named CEO carry-forward conditions one at a time through the CEO gate; keep intentionally-deferred conditions (UI-bound disclaimer, live-execution) explicitly open rather than silently rolling them into "done".

### 2026-07-30 — gold-signal-analyzer (Cycle 2) — verify every indicator against hand-computed values, and make each safety property a failing-if-violated test
- **What happened:** Built the analytical core on top of the Cycle-1 read-only scaffold — Phases 3 (candle build/aggregate/provisional), 4 (indicator engine), 5 (regime + independent scoring + veto/guards + confidence + risk plan), 8 (look-ahead-safe backtest), 9 (paper trading + journal + no-order guard). Done inline (not via cold subagents) because the phases are tightly sequential .NET and each gated on a real `dotnet test` before the next. 55 net-new xUnit tests (82→137) + 19 Python still green. Every indicator (SMA/EMA/MACD/RSI-Wilder/ATR-Wilder/Bollinger/ADX/Stochastic/OBV) asserted against a *hand-computed* expected value with the arithmetic documented in the test, not "does not throw." The dangerous properties are each a dedicated test that fails if the property regresses: Buy/Sell independence (`Sell != 100 − Buy`), look-ahead safety (`LookAheadSafeWindow` throws on a future index; a peeking strategy faults inside the engine), and no-order-path (reflection over `IMt5BridgeClient` finds no trade verb; `PaperBroker` has no reference to it). Confidence is computed from agreement/regime-fit/data-quality so a *high score can carry low confidence* — proven by test. The brief claimed "existing WPF placeholder screens"; there were none (Cycle 1 was headless), so Phase 6 UI was honestly deferred rather than faked.
- **Lesson:** "Verified against expected output" means a number you computed by another method, in the test, with the steps in a comment — pick tiny periods (RSI/ATR period 2, MACD 2/3/2) and clean datasets (linear series, pure trends where −DM≡0) so the expected value is hand-derivable and exact-ish (assert with a small tolerance for decimal EMA rounding). Population-vs-sample stddev, Wilder-vs-SMA seeding, and next-bar-vs-close fills are all silent correctness forks — pin each with a comment. Two cheap self-inflicted test bugs: an H4-bucket `expectedHour` typo, and `Candle`'s positive-price guard rejecting `low = close − 1` for small synthetic closes (use realistic price levels in fixtures). Independent buy/sell scoring is only real if the two draw from *separate evidence pools* — normalise each against the same max-weighted denominator but never subtract one from the other.
- **Rule going forward:** For any calc-heavy slice, each indicator/metric ships with a fixed-dataset test whose expected value is derived independently and documented inline; each safety invariant (no-fabrication / no-future-peek / no-order / independence) ships as a test that goes red the moment the property is violated. When a carried-over brief asserts an artifact exists ("existing WPF screens", "existing SQLite/EF setup"), verify it on the branch first — if it isn't there, build the testable pure-logic core and defer the shell honestly; never fake a dependency to look "done." Keep sequential, mutually-dependent implementation phases inline with a real build/test gate between each, rather than fanning out to cold subagents.

### 2026-07-30 — gold-signal-analyzer — enforce safety invariants in the type system / assembly graph, not in review
- **What happened:** Independent, from-scratch build of the MT5 connectivity bridge (FR-7…FR-12) as read-only scaffolding — no live terminal attach, and deliberately NOT reading the far-more-advanced sibling `gold-signal-analyzer-foundation`/`C:/gsa-f` implementation (owner chose an independent build to get a true second opinion). .NET 8 clean architecture (5 projects) + a stdlib-only Python loopback bridge. 101 tests green (82 xUnit Release + 19 unittest, including a real ephemeral-port HTTP round-trip proving 401-without-token / 200-with). The dangerous invariants were made *structural*: fabrication impossible because the live seam throws unless Connected+mapped and freshness defaults to not-fresh (future-dated tick → Stale); secrets impossible because the config record has NO secret member (reflection test fails the build if one is added) and the token comes only from env; the test provider is gated out of production by living in a **separate assembly the production projects don't reference** — verified physically (`ls` of the Release output shows no `Testing.dll`, `deps.json` grep = 0), not by a runtime flag.
- **Lesson:** For a data/connectivity foundation, "build the seatbelts before the engine" — prove the safety envelope against fixtures before any live attach is switched on. Make each invariant a construction-time or assembly-graph failure rather than a review checklist item, so it can't regress silently. Environment gotchas paid once: DPAPI needs the `System.Security.Cryptography.ProtectedData` package on net8; Python 3.9 chokes on `str | None` annotations without `from __future__ import annotations`; port 0 is a legitimate ephemeral-bind value and must be allowed in host/port validation. Mirror shared logic (gold symbol scoring) on both sides of a language boundary and test both so they can't drift.
- **Rule going forward:** When a slice's whole value is a safety property (no fabrication / no secret / no exposure / no live-execution), encode it structurally: throw-not-return on the unsafe path, no-secret-member config proven by reflection, test/mocking code in a non-referenced assembly proven absent from the Release output, loopback-only enforced at construction on BOTH the client and server side. Keep the live/irreversible seam guarded and unwired until a named approver signs off — ship the envelope first. For an "independent build" instruction, treat the sibling implementation as strictly off-limits (don't read it) and note the constraint in the brief.
