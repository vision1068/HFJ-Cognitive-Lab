Both reviewers independently returned PASS-WITH-CONDITIONS. The architecture's structural safety story held up under attack from both angles and neither could break the core invariants by reading source:

- **Verified sound by BOTH:** no-order §9 interface preserved (byte-exact, `MarketDataPortShapeTests` stays green); loopback is *unrepresentable* not merely rejected (ADR-14, 127.0.0.1 literal + integer-port-only, handshake `host` ignored, no IPv6 dual-stack ambiguity); `AccountSnapshot=null` is the honest answer to the bridge's monetary suppression (ADR-13); token-via-stdin-only forbids both args and env (ADR-15/AC-48.1); `run_bridge` structurally never calls `connect()` so `Mt5BridgeClient` touches zero MetaTrader5 (the AC-47.6 *property* is true even though its stated *test* is not — see C-B1); spec/diagram-first discipline met.

## Orchestrator reconciliation notes (decisions folded into the contract)

1. **Spawn smoke test (reconciles C1 with genuine end-to-end evidence).** QA is right that AC-47.6's *invariant* must be proven by the .NET `FakeBridgeTransport` (exactly one `GET /health`, zero reads) — that is the authoritative proof and needs no Python. **Additionally**, because both `python` (3.9.13) and `py` (3.14.6) are present on PATH here, Phase 3 SHOULD ship a **skippable integration smoke test** that spawns the real `run_bridge.py`, completes the stdin-token/`{ready,port}` handshake, asserts `GET /health` → 200, and asserts a read command (`copy_rates_range`) returns `ok:false, error:"handler_error"` (proving the bridge is up but **no terminal is attached** — the real gateway's `mt5` is `None`). This uses the **real** gateway (not a fake), so it does not resurrect the unsatisfiable clause; it is genuine command-output evidence of transport liveness + the not-connected reality, and it MUST skip cleanly when no interpreter is found (C15). It is supplementary, not the invariant proof.

2. **ADR-15 amended (C5).** No-orphan guarantee is **graceful-path only**; hard-kill-of-host orphaning is an **honest documented residual**, out-of-scope this slice, consistent with ADR-16 keeping the client portable. A Windows Job Object is the future hardening and would carry `[SupportedOSPlatform("windows")]` when added.

3. **Live-mapping honesty (C8).** The `symbol_info`→`SymbolSpecification` and rate→`Candle` field mappings are asserted only against fixtures this slice; their correctness against a **real Exness terminal is an explicit unverified-until-live confirm-item (C-live)**. The guard-throws-on-missing-key requirement ensures a wrong mapping fails loud rather than fabricating a zero.

4. **Confirm-items carried to the user (unchanged from arch §9, plus one):** **C1-conf** `ConnectAsync`=transport-liveness semantics; **C2-conf** `AccountSnapshot=null`; **C3-conf** branch-protection arming (now also a merge gate, condition C4 above); **C-live** field-mapping correctness unverifiable until a real terminal.
